# Site-wide SEO audit — 2026-05-18

**Scope:** 18 marketing pages on vectismail.com (home, features, pricing, about, contact, alternatives index + 5 sub, /for/ index + 4 personas, privacy, terms, getting-started).
**Methodology:** Live URL probing + Astro source review + cross-reference against [`marketing-seo-roadmap.md`](../../notes/marketing-seo-roadmap.md) (draft 2026-05-12). PSI perf data captured separately in `docs/audits/pagespeed/`.
**Toolchain:** curl + grep against rendered HTML (static-built Astro JSON-LD is in the markup; this is reliable for our site, would not be for a JS-rendered competitor).

## Executive summary

**Overall posture: strong.** The roadmap's Phase 1 is substantially complete, and a chunk of Phase 2 (use-case pages + first deliverability pillar) has been shipped since the roadmap was written. Most technical foundations are correct: 18 pages have correct trailing-slash self-canonicals, robots.txt explicitly allows every major AI bot, sitemap auto-generates from 30+ URLs, llms.txt/llms-full.txt are 200.

**Top 3 priorities surfaced by this pass:**

1. **Meta description bloat across 11 pages** — descriptions of 175-260 chars are getting truncated in SERP. Cheap to fix, immediate CTR effect.
2. **Schema gaps on the legal + contact pages** — `/privacy/`, `/terms/`, and `/contact/` have **zero** JSON-LD. Roadmap calls for `ContactPage + Organization` on /contact/; legal pages should at minimum have `WebPage` + breadcrumb. Cheap, mechanical fix.
3. **Home is missing FAQPage schema** on the "vs Mailcow/SendGrid/Manual Postfix" comparison cards — these are factually FAQ-shaped content (Q/A pairs), and FAQ schema is the single biggest AEO citation lever. Roadmap specifically called this out.

**Quick wins (under 1 hour each, sub-30min usually):**

- Trim meta descriptions to ≤155 chars on 11 pages
- Truncate 3 titles >60 chars
- Add `ContactPage + Organization` schema to /contact/
- Add `WebPage` schema to /privacy/ and /terms/
- Add `FAQPage` schema to home for the comparison cards
- Add `noindex` to `/account/billing/done/` (already on the v0.1.13 deferred list as P9-M4) — confirmed in sitemap right now

## Technical SEO findings

### ✅ Confirmed strong

| Area | Evidence |
|---|---|
| **AI crawler access** | robots.txt explicitly allows GPTBot, ChatGPT-User, OAI-SearchBot, ClaudeBot, anthropic-ai, PerplexityBot, Perplexity-User, Google-Extended, Bingbot, Applebot, Applebot-Extended, and `*`. Best-practice. |
| **Sitemap** | /sitemap-index.xml → /sitemap-0.xml with 30+ URLs. Auto-generated by @astrojs/sitemap. |
| **Canonical tags** | All 18 audited pages have self-referencing canonicals using the trailing-slash form (matches Astro `trailingSlash: 'always'` shipped today). |
| **HTTPS / TLS** | TLS 1.2+ enforced. HSTS preload-eligible (per Phase 8 audit). |
| **Mobile-friendly** | Responsive, single CSS bundle, no separate mobile site. |
| **URL structure** | Lowercase, hyphenated, descriptive, no params except `?reason=pro` on /contact/. Trailing slash consistent post-today's fix. |

### 🟡 Findings to address

**T1 — `/account/billing/done/` in sitemap but should be noindex/disallowed**

`https://vectismail.com/account/billing/done/` is currently a sitemap entry. It's a thank-you-after-Stripe redirect destination, not content. Should either:
- (a) Add `<meta name="robots" content="noindex,nofollow">` to the page AND filter it out of the sitemap, OR
- (b) Disallow it in robots.txt AND filter it from sitemap

**Status:** Already in the v0.1.13 deferred list as P9-M4 — verified still pending.

**T2 — Sitemap missing `lastmod` per URL**

The auto-generated sitemap from @astrojs/sitemap is using its defaults, which sometimes omit `<lastmod>`. Google uses lastmod to prioritise crawl. Worth checking the sitemap output:

```bash
curl -fsS https://vectismail.com/sitemap-0.xml | head -3
```

If lastmod isn't present, configure @astrojs/sitemap with `customPages` + per-page lastmod or use file mtime.

**T3 — OG image is a generic site-wide `/og/default.png`**

Every page uses the same OG image. Roadmap calls this out (Phase 9-L3 in the audit signoff). For high-value pages (alternatives/*, /pricing/, /for/*) bespoke OG cards measurably improve social CTR. Lower priority than the schema/meta gaps.

**T4 — Internal linking from home is healthy; from /alternatives/ is thinner**

Home links cleanly into /features/, /pricing/, /alternatives/, /alternatives/sendgrid/, /getting-started/, /pricing/, github. /alternatives/index/ links out to the 5 sub-pages but doesn't have lateral links between siblings (e.g. /alternatives/mailcow/ doesn't link to /alternatives/iredmail/). Adding "Other alternatives" footer-internal-link block on each alt page would help PageRank flow and AEO citation graphs.

## Content findings

### C1 — Phase 1.5 "first-150-words direct answer" audit is owed

The roadmap's Phase 1.5 says every page should answer "what is this page about?" in the first paragraph, in plain language, without burying the lead. Per AEO best practice this is the single biggest citation lever. **Not yet done** — every page needs a per-page review. From sampling, /pricing/ does this reasonably ("Self-hosted email platform — free Starter tier, $29/tenant/month Pro"), home does it ("Self-hosted email server. Your rules."), but several pages bury the value prop under marketing flourish.

### C2 — SendGrid alt page schema drift suggests content drift

The SendGrid alt page is missing `UnitPriceSpecification` and `QuantitativeValue` that the other 4 alt pages have. This implies the SendGrid page doesn't have the same cost-comparison block. Worth a content-parity review: are all 5 alt pages structured to the same template, or did SendGrid get a custom treatment? The roadmap defined a strict template (lead → at-a-glance table → "when to pick which" → detailed comparison → migration → CTA) and consistency matters for both SEO (predictable internal-link patterns) and AEO (LLMs cite from predictable structure).

### C3 — /alternatives/ index lacks FAQ-schema content

Roadmap (Phase 1.3) suggested adding FAQPage to alternative-related pages. The 5 sub-pages have FAQ; the **index page** does not. Adding 3-5 "which alternative should I pick if I'm coming from X?" Q/A pairs to /alternatives/ would compound the per-page FAQs into a citation-friendly summary page.

### C4 — Empty schema slot for the BSL license model

This is a positioning thing more than a schema thing. The BSL license is a real differentiator. Currently it surfaces as FAQ text on /pricing/ but isn't structured anywhere AI-readable. Could be: dedicated `/licensing/` page (Phase 3 candidate) or expand the BSL FAQ block. Worth a strategic decision before implementing.
